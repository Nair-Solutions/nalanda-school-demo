# ADR 0002: Locale-prefixed routes with typed dictionaries

- Status: Accepted (2026-10-25)

## Context

The brief needs a first-visit language choice, a persistent toggle that keeps the current page, real Hindi translations of every interface string, and a correct `lang` attribute.

## Decision

- Routes: `/en/*` and `/hi/*`. The URL is the source of truth for the language.
- `/` is the language chooser. A functional cookie (`NEXT_LOCALE`, 1 year, `SameSite=Lax`) set on choice or toggle lets `src/proxy.ts` skip the chooser for returning visitors.
- Strings live in `src/i18n/dictionaries/en.ts` and `hi.ts`. `hi.ts` is typed as `Dictionary`, so missing or extra keys fail the build.
- `tests/unit/dictionaries.test.ts` fails if a Hindi value equals the English or contains stray English words. `tests/e2e/routes.spec.ts` scans every rendered Hindi page for English words outside an allow-list (names, acronyms, the motto).
- Proper nouns stay in their source form and are marked `lang="en"` where they appear in Hindi pages (the motto, student names, the logo wordmark).

## Alternatives

`next-intl`: mature, but adds a dependency for features not needed here (ICU plurals, number/date formatting). Easy to adopt later if needed.

## Consequences

Deep links from search engines open directly in the linked language without the chooser. That is intentional: the chooser only guards `/`.
